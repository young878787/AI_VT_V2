# 隔離式 Headless Chat 測試設計

## 目標

20 輪或互動式測試不得讀寫正式的 `backend/memory/`。每次執行都應能獨立追溯；中斷、逾時或模型錯誤時，保留已完成輪次與明確的失敗原因，不把後續未執行輪次當成結果。

## 執行與資料隔離

`backend/tools/chat_test_cli.py` 自行在 loopback 暫用埠啟動一個沒有 reload 的後端子程序。子程序透過 `AI_VT_MEMORY_DIR` 將所有記憶檔導向本次執行目錄；正式後端及正式記憶不參與。CLI 管理子程序生命週期，無論成功、失敗或中斷都關閉它。既有連外 `--url` 模式停止支援，避免誤連正式服務。

每次執行建立 `backend/log/chat_test_runs/<run-id>/`：

- `memory/`：獨立的 profile、notes、session 與 emotion state。
- `turns.jsonl`：僅本次執行的逐輪原始結果。
- `report.md`：每輪完成後重寫的可讀摘要，包含狀態、已完成／計畫輪數、錯誤與報告路徑。
- `server.log`：測試後端輸出，供定位 API 或 WebSocket 錯誤。

報告記錄 run ID、情境來源與內容雜湊、使用的模型設定、每輪訊息、JEV 六欄位與來源、表情、記憶變更、延遲及重試次數；不記錄 API 金鑰。

## 失敗語義

後端啟動、連線或單輪對話有明確逾時。單輪錯誤可依 `--retries` 重試；重連時使用本次執行專屬的持久化 session ID，保留已完成對話。重試耗盡後寫入一筆失敗輪次，標記整次執行為 `failed` 並停止，不發送後續題目。若已有可見回覆但本輪後續步驟失敗，直接停止，避免重複執行可能已產生的記憶操作。中斷標記為 `interrupted`，保留部分報告。

## 驗證

使用單元測試檢查路徑隔離、run 目錄與報告格式、逐輪增量保存、失敗停止、重試與中斷清理；不依賴真實 OpenRouter API。README 更新為單一隔離測試指令與報告位置。
