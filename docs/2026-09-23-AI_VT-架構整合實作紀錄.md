# AI_VT 架構整合實作紀錄

依據：[架構整合調整計劃](./2026-09-23-AI_VT-架構整合調整計劃.md)與[架構摘要](./AI_VT_Architecture_Summary.md)。

## 已落地

| 階段 | 結果 |
| --- | --- |
| P0 | 正常客戶端每輪只收到一份 `expression_plan`；舊 `behavior`／`blink_control` 只有明確要求 `legacy_payloads` 才發送。Chat 關閉支援 provider 的 thinking，設定輸出上限。 |
| P1 | 文字與 ASR 使用相同後端正規化；`turn_id` 貫穿情緒、文字、Action 與 TTS。reader 與 turn task 分離，新輸入取消舊輪；前端過濾舊輪事件。JEV、Chat、Action 共用本輪固定情緒與相關記憶快照。 |
| P2 | Chat 逐段送出並跨 chunk 隱藏 thinking／狀態標籤；上下文有固定 token 預算。`stream_end` 在文字完成後送出。輸入接受時持久化 Memory 待辦，worker 單序列執行；operation id 與資料原子寫入，reset epoch 防止舊工作回填。Chat／Memory 可用各自 provider 與模型設定。 |
| P3 | WebSocket、Debug Panel 與手動控制接入前端 Action Scheduler；Scheduler 管理優先權、中斷、最新待辦與短反應冷卻，再由 Live2D adapter 套用 plan。模型切換、重設與斷線取消動作；後端接收 `action_state`。 |
| P4 | `memory_records.json` 保存類型、重要度、TTL、來源、狀態與使用次數；舊 `memory.md` 備份後匯入，並保留相容檢視。關聯檢索最多 5 筆、800 字；過期或低保留分數只封存。背景長期摘要帶來源 ID，原紀錄不被覆蓋。session 對話摘要獨立存放。 |

P5 在原計劃標為後續：長期 Emotion Pattern 與新的跨 Avatar 動作協議尚未落地。現有 `expression_plan` sequence、motion 與 idle 仍供多段表演使用。

## 驗證

- 後端 `unittest discover`：152 個測試通過；包含輪次取消、串流標籤、上下文預算、記憶去重與 reset epoch。
- 前端 `npm run build`、expression plan 與 emotion state 契約檢查通過。
- 隔離式 CLI 一輪完成：情緒 0.63 秒、Action 1.14 秒、首段文字 4.65 秒、文字完成 5.12 秒、Memory job 為 `done`。這是單次端到端樣本，不能推論效能改善。
- 修改到的前端服務、Debug Panel、參數面板與型別檔之 ESLint 通過。全專案 `npm run lint` 仍有既存的 SDK、宣告檔與控制面板 lint 錯誤。

## 限制

- 目前只有單使用者、單程序的本機持久化佇列；部署為多 worker 前需要可交易的共享儲存。
- OBS 使用主頁 Canvas 鏡像；尚未做瀏覽器中的手動視覺驗收。
- 記憶摘要使用背景模型，失敗時保留原紀錄並待下次重試。
